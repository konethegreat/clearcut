# ClearCut and TimeLex

_Short, dated, newest first. Written by Kone Tshivhinda & Claude. TimeLex's side of the relationship is its [ADR-0008](https://github.com/konethegreat/timelex/blob/main/docs/adr/0008-clearcut-relationship.md): separate repositories, one API contract, no shared crates, ClearCut owns the invoice maths and the export rendering, TimeLex owns capture, time, WIP and pro-forma assembly._

## 2026-10-26: answers to TimeLex's request list (A to D)

**Status words used below:** *exists* (built, tested), *next* (on [LAUNCH.md](../LAUNCH.md), built in that order), *proposed* (a design we want TimeLex to react to), *no* (deliberately not done).

### A. The contract

| Request | Answer |
|---|---|
| Keep `POST /v1/invoices/calculate` and the MCP tool `calculate_invoice` stable and versioned | **Exists, and promised.** Everything under `/v1/` only gains optional fields. A breaking change is a new `/v2/` path with `/v1/` kept for a stated period. Errors are always `{ "error": "<sentence>" }` with the usual status (`400`, `401`, `403`, `404`, `409`, `413`, `415`, `422`, `503`); a `401` is identical for every failure; a `403` names the missing scope. The MCP tool has the same input and output as the REST call. |
| Publish an OpenAPI file | **Built (26 Oct 2026):** [`contracts/openapi.json`](../../contracts/openapi.json), OpenAPI 3.1, every REST route with its required scope, status codes and bodies; the shapes of `Invoice`, `InvoiceTotals` and `PageReading` come from the core types themselves. It is **generated from the code** and a test fails when the checked-in file is stale; another test sends a request to every documented route and fails if the server does not know it, and another that every reference resolves. Read it with `gh api repos/konethegreat/clearcut/contents/contracts/openapi.json`. The route list is written by hand, so a route added without being documented is not caught: that is the one gap. |
| Take line values as given in cents; compute only category subtotals and VAT | **Built (26 Oct 2026).** A line takes an optional `line_total` (minor units, excluding VAT, same currency as `unit_price`). When present it is used **as given** and `quantity_milli` and `unit_price` are informational; when absent the line is `quantity_milli` times `unit_price` (half away from zero), exactly as before, so existing callers are unchanged. VAT is still taken **per tax category on the category subtotal, not per line** (`Invoice::totals`). Same endpoint (`POST /v1/invoices/calculate`), same MCP tool, additive, so no version change. **The test pair** (tested in the core and through the endpoint): 1.5 hours at R333.33 is R499.995, which is computed as R500.00 (net R500.00, VAT R75.00, gross R575.00); given as R499.99 it stays R499.99 (net R499.99, VAT R75.00, gross R574.99). The TypeScript SDK type has the optional field. |
| Configure `rmcp` safely; TimeLex reports 3.6.0 serves 2026-07-28 statelessly | **Checked, and that is not what the SDK says.** The `rmcp` 3.6.0 release notes (20 Oct 2026) list *"server: reject requests to 2026-07-28 clients"* as a fix, and 3.7.0 (22 Oct 2026) adds nothing about it. So the Rust SDK **still serves 2025-06-18 only**, and our note about 3.5.1 stands. We will move to the 2026-07-28 spec (ClearCut P1-06, TimeLex P1-08) when the SDK serves it, or implement the stateless HTTP transport ourselves if that takes long; we will tell you which before we start. Re-check it against the release notes at each `rmcp` release rather than relying on either project's summary. |

**How each call behaves if repeated** (so a retry is safe): `calculate` is pure. `POST /v1/documents` is idempotent on the file's content (the same bytes from the same tenant return the same document and job). Confirming a review is refused if the page is no longer waiting (`409`). `DELETE` of a deleted document is `404`. A general `Idempotency-Key` header for every mutating call is **next** (P1-05).

### B. The quality gate pattern
**Exists** in `crates/clearcut-eval`, decided in [ADR-0010](../adr/0010-gold-set-and-evaluation.md), with the guides in [`docs/gold-set/`](../gold-set/README.md). The pieces, in the order they matter:
- **Label format:** one `label.json` per case; every amount is **decimal text** (`"1150.00"`), never a float, so a label can be compared to the cent.
- **Scorer outcomes per field:** exactly one of correct, wrong, missing, spurious. A **silent critical error** is a wrong critical field (an amount, a date, a number, a VAT figure) that the pipeline did not send to a person. The **release gate** is zero of those on the test split, with the other limits in ADR-0010. The dev split is for tuning, the test split is not looked at while tuning.
- **Repository guard:** `clearcut-gold guard .` fails CI if a real document or a gold-set label is anywhere outside the approved folders in `gold-guard.json`, so real data cannot be committed by accident.
- **CI checks:** the guard, the scorer on the synthetic sample, a personal-data safety net on labels, and the licence check on the Python worker.
- The scorer is generic over the label format (it knows fields and outcomes, not invoices) and can be reused. **Proposal accepted:** a `contracts/examples/` folder of golden request and response files that both repositories test against; it ships with the OpenAPI file. **cargo-mutants nightly:** we have run mutation checks by hand on the risky changes, and will evaluate a nightly job; not committed to yet.

### C. Pro-forma documents, and tenants
- **Pro-forma in:** the document kinds will include a structured **pro-forma** (JSON, not a PDF) that is read, checked and given events like an invoice, and **never takes a gapless invoice number**. Numbering belongs to issuing (ClearCut Phase 6), which is **later** (see LAUNCH.md section 4). The request shape should be your `ProFormaRequest`; send us a sample and we will make it a contract test. Proposed, not built.
- **Programmatic tenants:** today a tenant and its first key are created by the operator's command (`clearcut-admin create-tenant`, `create-key`), and a tenant's administrators can manage further keys over the API (`keys:admin`). **No** tenant-creation endpoint exists. **Proposed:** `POST /v1/tenants`, accepted only with an *operator* credential (separate from tenant keys, never a tenant key), so TimeLex can provision a tenant per firm. Say if that is what you need, and we will design it with its own review.

### D. The Anthropic key lifecycle (one page)
ClearCut uses **only the Anthropic API, and the project has no key of its own**: whoever runs it supplies a key, and every call is billed to them ([ADR-0011](../adr/0011-bring-your-own-anthropic-key.md)).
- **Mode A (exists):** one owner on their own computer: the key is in the environment or a file, held in a type that cannot be printed, never sent to the document worker, never in a log, an error, a URL or a job.
- **Mode B (next, LAUNCH item 1):** each **tenant** has its own key, stored **encrypted at rest** (AES-256-GCM, the tenant bound in so a stored value cannot be moved to another tenant, the master key from the environment and never in the database), **write-only** (set, replace, delete; afterwards only the last four characters and whether it works are visible), checked with a free call when set, audited. The job runner uses the tenant's key. An operator switch turns the shared key off so that on a deployment every tenant must bring its own. **For TimeLex:** set the key through the API once per tenant; ClearCut never gives it back. We do **not** accept a key on each request, because jobs run after the request has ended.
- **Mode C (designed, deferred):** a key that exists only in memory for a browser session, for a hosted trial. It waits for a decision on who runs a hosted service ([ADR-0015](../adr/0015-try-it-deployment.md)).
- **Money safety, for any mode:** a per-document cap (R5) and a monthly budget (R100) in rand, checked **before** each call; a loop cannot run away; a missing tax or a figure the page does not show goes to a person instead of up the model ladder. Rate limits and spend caps of the key's owner are respected, not retried blindly.
- **Claims about Anthropic's service:** the ones ClearCut relies on are in [research 06](../research/06-anthropic-api.md) with their sources and the date they were read (for example: Fable 5.1 is a covered model with 30-day retention; the other models have no retention by default). We were not sent a list of TimeLex's claims to check; send it and each will be checked against Anthropic's own pages, with the result written here.

### E. What ClearCut will not do for TimeLex
Nothing outside the contract above. No shared crate (ADR-0008 decision 1), no TimeLex-specific code paths, no roadmap changes for TimeLex dates. If ClearCut is down, TimeLex queues pro-forma generation (ADR-0008 decision 7); ClearCut's own jobs queue and resume.
